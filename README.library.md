# 사유의 서재

PDF마다 핵심 개념을 재서술한 지식 라이브러리입니다. 왼쪽의 독립된 PDF 탭을 선택하면 해당 자료의 목차와 오른쪽 본문이 열립니다. PDF 탭과 목차가 따로 스크롤되므로 긴 자료를 읽는 중에도 다른 PDF로 전환할 수 있습니다. 서버나 외부 API 없이 실행됩니다.

## 실행

Node.js 20 이상에서 외부 패키지 설치 없이 실행할 수 있습니다.

```sh
npm test
npm run build
npm start
```

`http://127.0.0.1:4173`에서 확인합니다. `PORT` 환경변수로 포트를 바꿀 수 있습니다.

- `dist/index.html`: 일반 정적 웹사이트. 같은 폴더의 CSS/JS 파일과 함께 사용합니다.
- `dist/library.html`: CSS, JavaScript, 지식 데이터를 포함한 독립 실행 파일. 브라우저로 바로 열 수 있습니다.
- 일반 정적 호스팅에는 `dist` 폴더를 사용합니다.

## GitHub Pages 배포

공개 주소: https://linjingzhu.github.io/library/

기존 GitHub Pages 설정인 `stable` 브랜치의 루트(`/`)에서 게시합니다. 별도 유료 서비스나 사용자 정의 Actions 워크플로 없이, 로컬에서 생성한 독립 HTML을 게시합니다.

```sh
npm test
npm run build:pages
```

`index.html`과 `.nojekyll`은 `scripts/build.mjs --pages`로 생성하는 게시 파일입니다. 직접 수정하지 말고 `src/` 또는 `content/`를 수정한 뒤 이 명령으로 재생성합니다. 생성물과 소스를 함께 커밋하고 검토 후 `stable`에 병합하면 기존 Pages 게시 과정이 실행됩니다. 배포 완료는 GitHub Pages 상태와 실제 주소의 응답으로 확인합니다.

## 기능

- PDF별 독립 탭 → 해당 자료의 목차 → 핵심 요약과 세부 개념 → 실천 질문
- 모든 페이지의 고정 헤더 중앙에서 전체 PDF의 본문·제목·키워드, 자료 소개·저자·출처 안내 및 편집 연결을 입력 즉시 검색, Ctrl/Cmd+K로 입력창 이동, Esc로 결과 닫기
- 주제별 책갈피, 최근 읽은 주제, 글자 크기 조절
- 책 사이의 개념 연결, 자료와 읽기 안내
- 해시 주소를 이용한 직접 링크와 브라우저 뒤로/앞으로
- 반응형 화면, 키보드 탐색, 검색 대화상자, 인쇄용 화면
- 사용자가 선택한 로컬 PDF 원문 열기

책갈피·최근 읽은 주제·글자 크기는 `localStorage`에 저장됩니다. 기기 간 동기화는 하지 않습니다. PDF는 브라우저 객체 URL로만 연결되며 업로드하지 않습니다. 창을 닫으면 PDF 연결은 해제됩니다. 원문 PDF와 OCR 전문은 저장소 및 배포 결과에 포함하지 않습니다.

## 자료 구조

| 파일 | 원문 | 범위 |
| --- | --- | --- |
| `content/conflict.json` | 행복한 커플은 어떻게 싸우는가 | 원리, 갈등 유형, 5가지 실수와 실천, 회복, 결론 및 안내 |
| `content/love.json` | 5가지 사랑의 언어 | 본문, FAQ, 검사 실시·채점·해석 방법 |
| `content/tao.json` | 노자의 말 | 001–145 전체 항목, 서문 및 권말 해설 |

원문은 총 952쪽(466 + 256 + 230)의 이미지 기반 PDF입니다. 로컬 한국어 OCR로 전체를 읽고, 각 책의 목차와 본문을 대조하여 핵심 내용을 재구성했습니다. 페이지 번호는 **첨부 PDF의 물리 페이지(첫 쪽=1)**이며 인쇄된 쪽수와 다를 수 있습니다.

본문은 재서술한 학습용 요약입니다. `practice`와 책 사이의 연결은 편집 제안이며 저자의 직접 인용이 아닙니다. 광고, 빈 쪽, 참고문헌 전문, 사례의 모든 세부와 검사 문항 전문은 재수록하지 않습니다. OCR 모든 글자를 이미지와 일대일 대조한 정밀 교정은 하지 않았습니다.

각 책의 `chapters` 항목은 다음 구조를 사용합니다.

```json
{
  "id": "love-01",
  "title": "주제 제목",
  "part": "목차 묶음",
  "pages": [2, 16],
  "summary": "핵심 요약",
  "points": [{ "title": "개념", "text": "설명", "page": 6 }],
  "practice": ["편집자가 제안하는 실천 질문"],
  "keywords": ["검색 키워드"]
}
```

쪽수와 읽음 완료 표시는 사용자 화면에 노출하지 않습니다. 출처 페이지 데이터는 편집·검증용으로 유지합니다.

`point.page`는 선택값입니다. 없으면 주제의 `pages` 범위를 근거로 검증합니다. `tao` 항목은 원래의 001–145 번호를 `points.title` 앞에 유지합니다.

## 구성과 검증

### 새 PDF 추가

1. PDF를 분석하고 아래 메타데이터와 기존 `chapters` 형식으로 `content/<고유-id>.json`을 추가합니다. 원문을 파일 선택기로 연결하는 것만으로 분석 내용이 생성되지는 않습니다.
2. `npm test`와 `npm run build:pages`를 실행합니다. `content/`의 모든 JSON을 자동으로 읽어 새 PDF의 탭·목차·본문·검색·자료 안내를 생성합니다. UI나 빌드 코드에 ID를 추가할 필요가 없습니다.
3. 새 탭과 출처를 확인하고 생성된 `index.html`을 소스와 함께 배포합니다.

```json
{
  "id": "new-pdf",
  "title": "새 PDF 제목",
  "author": "저자",
  "description": "자료 소개",
  "pages": 100,
  "order": 40,
  "category": "분야 · 주제",
  "color": "blue",
  "coverImage": "new-pdf.png",
  "notes": ["분석 범위와 출처 안내"],
  "chapters": []
}
```

`chapters`에는 앞서 설명한 형식의 주제를 최소 한 개 넣어야 합니다. 자료 ID와 각 주제 ID는 전체 서재에서 고유해야 하며 영문 소문자·숫자·하이픈을 사용합니다. 기존 ID를 바꾸면 직접 링크와 저장된 읽기 기록이 이어지지 않습니다. `order`는 작은 값부터 정렬하며 생략 시 1000, 동률일 때 ID 순입니다. `category`와 `color`는 선택 사항이며 색상은 `blue`, `rose`, `sage`를 지원합니다. 기존 세 자료의 편집 연결은 ID로 연결되어 새 자료를 앞에 추가해도 바뀌지 않습니다. 새로운 비교 해석은 별도 편집이 필요합니다.

### 파일 구성

표지 이미지는 `assets/covers/`에 보관하고 `coverImage`에 파일명을 지정합니다. PNG·JPEG·WebP를 지원하며 파일명에는 영문 소문자·숫자·하이픈을 사용합니다. 표지가 없으면 이 필드를 생략하면 기본 표지가 표시됩니다. 빌드 시 이미지를 데이터 URI로 포함하므로 일반 웹사이트와 독립 HTML 모두 외부 이미지 경로 없이 열립니다. 제공된 원본 비율을 유지해 책장과 자료 소개에 표시합니다.

- `src/`: UI와 상호작용 원본. 외부 폰트·이미지·스크립트 의존성 없음.
- `assets/covers/`: 사용자가 제공한 각 도서의 표지 원본.
- `content/`: 편집 가능한 한국어 지식 데이터.
- `scripts/build.mjs`: 데이터 결합 및 단일 HTML 생성. `dist`는 생성물이므로 직접 수정하지 않습니다.
- `scripts/catalog.mjs`: JSON 자동 탐색, 정렬, 중복 ID·필수 필드·출처 쪽수 검증. 잘못된 자료는 게시 파일 생성 전에 빌드를 중단합니다.
- `scripts/serve.mjs`: 127.0.0.1 전용 로컬 정적 서버.
- `tests/content.test.mjs`: 출처 페이지 범위, 탐색 ID, 필수 내용, 노자 145항목 누락/중복 검증.
- 기존 AI 개발 정책 파일은 유지합니다. 프로젝트 기능 설명은 이 문서에 한정합니다.

검증은 데이터 구조 검사와 실제 브라우저에서의 탐색·검색·저장·원문 연결·반응형 화면 확인을 구분합니다. 내용 범위 검사만으로 모든 요약의 의미 정확성을 증명하지는 않습니다.
